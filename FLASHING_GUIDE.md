# FLASHING_GUIDE.md — whyred → Proxmox VE (read fully before touching the device)

> **Everything below is executed by YOU, the device owner.**
> The build pipeline stops at `dist/` artifacts; it never talks to hardware.

## 0. What you need

| Item | Why |
|------|-----|
| Xiaomi Redmi Note 5 Pro (`whyred`), bootloader **unlocked** | ⚠️ the surveyed unit is LOCKED (`unlocked:no`, anti v4) — Mi Unlock first (§1) |
| **Verified backup of `boot` + `userdata`** | mandatory before anything below; flashing overwrites both |
| USB-A ↔ USB-C data cable | fastboot + RNDIS |
| `platform-tools` (adb/fastboot) on any host | flashing |
| Optional: UART 3.3V adapter @ BLSP1_UART2 pads (115200 8n1) | bring-up debug |
| Stock MIUI fastboot ROM for whyred | unbrick insurance (EDL / test point) |

The large `.img` artifacts are **not stored in git**. Rebuild them with
`scripts/build-edk2.sh` and `scripts/build-rootfs.sh` (Lima VM); only the
kernels and `dist/SHA256SUMS` are tracked.

## 1. Unlock the bootloader (one-time)

1. Add Mi account in Settings → My device → all specs → tap "MIUI version" 7×
   → Developer options → OEM unlocking + Mi Unlock status bound.
2. Run Xiaomi's **Mi Unlock Tool** on Windows with the same Mi account;
   wait out the binding period (168 h historically).
3. Verify lock state via `fastboot getvar unlocked` → must say `yes`.
   ⚠️ NEVER run `fastboot oem device-info` on this ABL — it wedges the
   fastboot handler until physical reboot (measured 2026-08-23, EXP-002).
   ⚠️ `fastboot oem edl` is **not** supported by this ABL (Invalid Parameter);
   EDL requires the physical test-point route (docs/reverse-unlock.md).

`MiToolbox-Native` (`apps/unlocker/`) shows live unlock state and refuses
writes to unknown devices, unlocked=false, or partitions outside
boot/cache/recovery. It cannot bypass server-signed authorization — by design.

## 2. Artifacts and integrity

```
dist/
├── uefi_whyred.img              # Plan A: EDK2 UEFI payload (flash → boot)
├── boot_pve_whyred.img          # Plan B: mainline kernel+DTB (flash → boot)
├── pve_rootfs_arm64.img         # raw ext4 rootfs (Proxmox VE arm64)
├── pve_rootfs_arm64.sparse.img  # same, Android sparse — flash this one
├── Image.gz-whyred              # kernel with appended DTB
└── SHA256SUMS                   # regenerated by scripts/make-dist.sh
```

Verify before connecting the phone:

```sh
./flash_all.sh --check                    # sizes + manifest, no device access
( cd dist && shasum -a 256 -c SHA256SUMS )
```

`--check` fails when an artifact is missing or a hash does not match;
`flash_all.sh` repeats the manifest check before its first write.

## 3. Flash sequence

**Default is Plan B** (mainline kernel through the stock ABL). Plan A
(experimental UEFI payload) is installed only after Plan B has booted and the
UART console is verified — see ADR-001.

```sh
adb reboot bootloader          # or VOL− + POWER from off state
DEVICE=whyred ./flash_all.sh   # checks product+serial, asks for typed confirmation
PLAN=uefi DEVICE=whyred ./flash_all.sh    # Plan A, only once Plan B is proven
```

The script refuses to run when: no device is in fastboot, several are
attached (set `SERIAL=`), `getvar product` ≠ `$DEVICE`, the bootloader is
locked, or the artifact hashes do not match.

Manual equivalent (explicit control, same order):

```sh
fastboot getvar product                      # must say whyred
fastboot getvar unlocked                     # must say yes
fastboot flash boot    dist/boot_pve_whyred.img
fastboot flash userdata dist/pve_rootfs_arm64.sparse.img
fastboot reboot
```

`misc` is **not** touched: the project's partition policy allows writes to
`boot`, `cache`, `recovery`, `userdata` only (docs/01-partitions.md).
`devinfo` is written only by the unlock procedure, and only with a backup.

**Rollback / unbrick**: re-flash the stock MIUI fastboot ROM with MiFlash in
EDL mode (test point under the SIM shield). This is the standard recovery
route for this board, but it has not been exercised on this unit — keep the
backup from §0 regardless.

## 4. First boot & access

| Path | Behavior |
|------|----------|
| Plan B (`boot_pve_whyred.img`) | ABL boots the mainline kernel straight away |
| Plan A (UEFI in `boot`) | SimpleInit/boot manager over panel fb → extlinux.conf → Linux |

- **Serial**: `screen /dev/cu.usbserial-* 115200` (macOS; Linux:
  `/dev/ttyUSB*`). The image ships with **no password**: root is locked, so
  log in on the serial console is not possible until you set one — run
  `passwd` from a recovery/root shell, or set it while in the initramfs/`init=/bin/sh`.
- **USB RNDIS Web UI**: connect cable to your computer → new NIC appears →
  set host IP `10.15.0.1/24` → browse **https://10.15.0.254:8006**.
- eMMC space beyond the 8 GiB rootfs image is unused until you grow the
  filesystem (`parted` + `resize2fs` on the `userdata` partition).

## 5. Post-install PVE checklist

```sh
passwd                                    # set the root password
pvecm create whyred-cluster               # optional clustering
pveam update && pveam available           # LXC templates (arm64)
lxc-checkconfig                           # all green = container-ready kernel
```

Create an LXC: Datacenter → storage `local` → templates → download an
arm64 Debian template (container userland is independent of the trixie host).

## 6. Troubleshooting

| Symptom | Action |
|---------|--------|
| No display, LED loop | UART console; flash the Plan B boot image |
| fastboot `FAILED (remote: size too large)` | sparse rootfs larger than the `userdata` partition; rebuild with a smaller `SIZE_MB` |
| UEFI boots but no disk | edk2-msm sdm660 eMMC driver + HS400 timing — capture the UART log, file upstream |
| RNDIS missing | check `lsmod g_ether`, `/etc/network/interfaces.d/usb0`, `dmesg \| grep dwc3` |
| fastboot stops responding | physical reboot; never `oem device-info` |
