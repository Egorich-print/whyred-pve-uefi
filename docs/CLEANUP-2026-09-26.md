# CLEANUP-2026-09-26 — what was removed from the tree, and why

> Follow-up to `AUDIT-2026-09-25.md`. Objective: leave the project without
> build junk or build outputs, with one command that recreates a clean state,
> and a record of every judgement call. No device was touched; no source
> feature was removed or redesigned.

## Why

The audit left the tree at about 1.4 GB: 749 MB of Cargo build caches, about
625 MB of physical `dist/` output, plus 32 KB of Python bytecode. (Sizes in the tables
below are from the start of the pass. Re-running `scripts/check.sh` rebuilds
~1.7 GB of Cargo output, which is expected; `scripts/clean.sh` removes it
again. The end state is 64 MB.) Most of it was untracked and reproducible. One part was both tracked *and*
generated — the Tauri schema dump and `capabilities/.keep`. The cleanup separates three things that had been
confused:

1. **inputs** — tracked source, docs, the two release kernels;
2. **build outputs** — `dist/*.img`, regenerable, not tracked;
3. **build caches** — `target/`, `__pycache__`, never needed after a check.

## What was removed

| Item | Size | Why it is safe |
|------|------|----------------|
| `tools/target/` | 109 MB | Cargo cache; `cargo build` recreates it |
| `apps/unlocker/src-tauri/target/` | 628 MB | same |
| `apps/unlocker/src-tauri/crates/mibox-core/target/` | 12 MB | same (a path dependency built standalone by one invocation) |
| `tools/__pycache__/` | 32 KB | Python bytecode; **no longer regenerated** (see below) |
| `apps/unlocker/src-tauri/gen/` | 36 KB | Tauri regenerates these schemas on every build of the app; `scripts/clean.sh` removes them again |
| `dist/uefi_{whyred,lavender}.img` | 12 MB | `scripts/build-edk2.sh` |
| `dist/boot_pve_{whyred,lavender}.img` | 32 MB | `scripts/build-rootfs.sh` |
| `dist/pve_rootfs_arm64.sparse.img` | 1.69 GiB apparent / 581 MB physical | `scripts/build-rootfs.sh` (the raw image still exists in the Lima VM) |
| `apps/unlocker/src-tauri/gen/schemas/*.json` (tracked!) | 298 034 B across 4 files | generated by `tauri-build`; `cargo check` does not need them, and tracking them made every Tauri build able to dirty the tree |
| `apps/unlocker/src-tauri/capabilities/.keep` (tracked, contains `{}\n`) | 3 B | placeholder, not a capability definition; the build script ignores it |

Kept on purpose: `dist/Image.gz-whyred` and `dist/Image.gz-lavender` (tracked;
a kernel rebuild is 40–60 min and 32 MB is cheap), both `Cargo.lock` files
(required by `--locked`), and `.git/` (not a trackable file, simply untouched).
`dist/SHA256SUMS` is kept and now covers exactly the two surviving kernels —
the removed build outputs are no longer represented in it.

## Changes that make junk stop coming back

- `tools/test_tools.py` sets `sys.dont_write_bytecode = True`, so importing the
  tools no longer creates `__pycache__/`.
- `scripts/check.sh` no longer runs `python3 -m py_compile`: it wrote bytecode
  regardless of `-B`, and the unit test imports every tool module, so syntax is
  covered anyway.
- `.gitignore` gained `*.pyc`, `*~`, `*.swp`, `*.swo`, `.#*`, `\#*#`,
  `dist/SHA256SUMS.*`, `dist/*.part`, `dist/*.partial`, `dist/*.tmp` and
  `apps/unlocker/src-tauri/gen/`; the duplicate `dist/backups/` entry was
  dropped (`backups/` already covers it).
- `flash_all.sh` now **requires** `dist/SHA256SUMS` instead of continuing when
  it is absent: an unverified artifact must not reach a phone.
- `tests/flash_all_test.sh` gained the matching cases ("artifacts without a
  manifest", "tampered artifact vs manifest") — 7 → 8 gate tests.
- `scripts/check.sh` now fails when `dist/SHA256SUMS` is absent, instead of
  printing a note and reporting success.

## Code debt removed (from the code-slice audit)

- Unused dependencies: `crc32fast` from `sparse-rs`, `clap` from `sahara-rs`,
  `anyhow` from `mitoolbox-native` — each declared and never referenced.
  `clap` remains in `sparse-rs` and `anyhow` in `sahara-rs`, where both are
  used; only the unused entries were removed.
- Dead code: `sparse_rs::write_all` (zero callers), the discarded
  `_major`/`_minor`/`_total_chunks` header reads, the ignored capacity argument
  of `Pending::new`, an always-true `is_multiple_of(4)` check, an unreachable
  `upload()` return branch and an unused `time` import in `edl-recon.py`, an
  unused `struct` import in the test, an unnecessary `pub` on a binary-local
  struct.
- Two safety defects, both found while reading for cleanup:
  - `edl-recon.py` ignored the byte count returned by `dev.write`; a short USB
    write is now a protocol error instead of a mysterious stall later.
  - `sahara-rs` picked the **first** EDL device (the Python uploader already
    refused when several were attached) and could index past a short HELLO
    packet. Both are now rejected explicitly.
- Test honesty: `test_tools.py::test_matches_rust_implementation_constants` used
  to compare a Python tuple with another Python tuple while claiming to check
  the Rust constants. It now parses `tools/sahara-rs/src/main.rs` and compares
  the real values, so a divergence fails the suite.

## Deliberately kept

- Both Sahara uploaders: the reason they coexist is documented and real
  (`rusb` does not enumerate this interface on the macOS host, `pyusb` does),
  and both now share the same tested transcript expectations.
- `bootimg info`/`unpack`/`pack`, `sparse-rs simg2img`, the two EDL tools and
  `analyze-devinfo.py`: operator tools with no scripted caller, all documented
  in `README.md` or `docs/reverse-unlock.md`.
- `raw_to_sparse_bytes`: a small in-memory wrapper used by the tests; removing
  it would only make the tests less readable.
- `.gitignore` entries for `edk2-msm/`, `rootfs/`, `build/`, `node_modules/`,
  `dist/*.fd`, `dist/*.bin` (six patterns): no current host path produces them,
  but a guest build or a future tool run inside a Lima-mounted directory would,
  and six lines are cheaper than a 2 GB accidental commit.
- Historical records: `REPORT.md` keeps its 2026-08-23 numbers and says so in
  its first line; `docs/AUDIT-2026-09-25.md` is dated in its title and keeps
  the pre-fix claims it records, but only `REPORT.md` is explicitly labelled a
  snapshot.

## The cleaning command

```sh
scripts/clean.sh              # caches and scratch (safe at any time)
scripts/clean.sh --dry-run    # show the plan
scripts/clean.sh --dist       # + reproducible dist images (refuses a dirty tree)
scripts/clean.sh --vm         # + build outputs inside the Lima VM
scripts/clean.sh --all        # caches + dist
```

`--dist` rewrites `dist/SHA256SUMS` for the surviving files so the manifest
never describes a file that is gone. `--vm` keeps the `edk2-msm` clone (a
rebuild costs 10–30 min) and the VM instance itself.

Safety rules, precisely: the default mode only removes paths that git does not
track — a tracked entry in the target list or scratch sweep aborts or is
skipped;
`--dist` and `--vm` refuse to run when the working tree is dirty, and `--yes`
is the explicit override for that check — it does not widen the path
allowlist. `dist/SHA256SUMS` is the one tracked file any mode rewrites, and
only so that it keeps describing the files that exist. `git clean` is never
used.

## Independent verification

An independent read-only agent checked A1–A8 from fresh evidence. First pass:
**FAILED** on four points, all of them real:

| Found | Reality | Fix |
|-------|---------|-----|
| `clean.sh` claims it never touches Cargo.lock files | it does remove `apps/unlocker/src-tauri/crates/*/Cargo.lock` — a gitignored per-crate build artefact | the header comment now names that one exception explicitly; the two tracked lockfiles are still protected |
| `clean.sh` sweeps scratch globs inside `backups/` | `backups/` holds forensic evidence (EDL logs, partition dumps) and a `*.log` there would have been deleted | `backups/` and `dist/backups/` are pruned from the sweep |
| `capabilities/.keep` still tracked | the earlier `git rm --cached` silently failed; the file held `{}` and is not a capability | untracked and removed; `cargo check` of the app still passes |
| docs claimed 7 gate tests | there are 8 (one was added with the manifest gate) | all three documents corrected to 8 |

It also caught a **false claim of my own**: `docs/AUDIT-2026-09-25.md` and this
file stated that the chroot no longer hard-codes the hostname. An earlier
patch had silently not applied, so `pve/vm-build-rootfs.sh` still contained
`hostname whyred-pve` inside the chroot — which both hard-codes the shared
rootfs to one device and renames the build VM through the shared UTS
namespace. It is now genuinely parameterised (`PVE_HOSTNAME`, default
`pve-arm64`) with no runtime `hostname` call, which is what ADR-004 asserts.

Two smaller items it raised were also fixed: `check.sh` used to treat an absent
`dist/SHA256SUMS` as a note and still print "ALL CHECKS PASSED" (now fatal),
and `test_tools.py` leaked an unclosed file handle when reading the Rust
constants.

The second pass rejected the fixes for the same class of bug: the `backups/`
prune was added to the scratch-glob loop but not to the `__pycache__` sweep, so
a cache directory inside `backups/` would still have been deleted. The prune
now covers every sweep; it was also tested functionally by planting
`backups/test-evidence/{edl-upload.log,__pycache__/x.pyc}` and confirming both
survived a dry run and a real run.

The third pass accepted the tree and rejected this document instead, on five
points: the dirty-tree refusal is bypassable with `--yes`; `--dist` does rewrite
a tracked file (`dist/SHA256SUMS`); `docs/lavender.md` still said "header v1"
without distinguishing stock from our own images; the `.gitignore` list was
called three lines when it is six patterns; and only `REPORT.md`, not the audit
record, was labelled a snapshot. All five are corrected above, including a note
that the size inventory is from the start of the pass — a verification run
rebuilds ~1.7 GB of Cargo output, which `scripts/clean.sh` removes again.

**Verified final state** after three recorded verification passes:
64 MB, no `target`/`gen`/`__pycache__`/logs/backups/temp outside `.git`,
`git status --ignored` empty, `git diff --check` clean, `shasum -c` green,
`scripts/check.sh` ALL CHECKS PASSED (25 Rust, 8 Python, 8 gate tests),
`scripts/clean.sh` a no-op on the second run, and every `rm` in `clean.sh`
either uses a fixed path or skips `backups/`.
