# AUDIT 2026-09-25 — full-project review and remediation

> Scope: every tracked file in `whyred-pve-uefi` (tools, scripts, build
> pipelines, Tauri app, docs, repo hygiene), reviewed with five independent
> sub-agent audits plus a direct pass. **No device was touched**: no
> `fastboot flash`, no `dd`, no EDL write, no unlock attempt.
>
> Commits: `fd0f155` … `627cae6` (audit fixes) and the follow-ups listed at
> the end. Everything is verified by `scripts/check.sh`.

## Method

1. Five parallel audits (Rust tools, shell/Python safety, build pipelines,
   docs consistency, repo hygiene/secrets), each instructed to read the code,
   discard false positives and propose the smallest fix.
2. Cross-checking against the project's own measured data
   (`docs/01-partitions.md`, `docs/exp002-getvar-all.txt`, Vivanta hardware
   notes) and against a proven reference implementation for protocol code
   (`~/ai-workstation/Tools/edl`, bkerler/edl) instead of trusting memory of
   the Sahara/fastboot grammars.
3. Triage by blast radius: wrong image → brick; wrong device → brick; wrong
   claim → wasted weekend.
4. Fix, then verify with one command (`scripts/check.sh`).

## Critical findings (device-damage class) — all fixed

| # | Finding | Consequence before the fix | Fix |
|---|---------|----------------------------|-----|
| 1 | `bootimg-rs` chose the header endianness by "does `kernel_size` plausibly fit" | A **little-endian** image whose payload length is a multiple of 256 (e.g. 1 MiB) is byte-swapped into a plausible-looking BE header → the tool silently unpacked a 4096-byte "kernel" instead of 1 MiB. A rebuilt image from that parse is wrong; flashing it bricks the device. | structural validation of each candidate (page size sane, version fits its header, all aligned sections inside the file); regression test `little_endian_kernel_multiple_of_256` |
| 2 | v3/v4 headers parsed at offsets 20/24 | valid v3/v4 images fell into the v0–v2 path | AOSP `boot_img_hdr_v3` layout (`header_size@28`, `cmdline@44`, `header_version@1580`, `cmdline_size@1584`), fixture corrected |
| 3 | `sparse-rs` never verified declared coverage | a truncated/short chunk list produced a correctly sized buffer with the tail silently zero-filled — a **truncated rootfs** would have been flashed | full-coverage assertion, unknown chunk types rejected, `checked_mul` + 64 GiB ceiling against a header-controlled allocation |
| 4 | `flash_all.sh` matched only the substring `whyred` and sent no `-s` | `DEVICE=lavender` aborted; the documented bypass wrote to whatever phone answered | product+serial identity checks, `-s` on every command, refusal with several devices attached, typed serial confirmation |
| 5 | `flash_all.sh` erased `misc` on every run with `\|\| true` | violated the project's own partition policy; a wrong-device run destroys boot-control state | erase removed entirely |
| 6 | `flash_all.sh` never compared hashes before writing | a corrupt or swapped image passed | `shasum -c` in `--check` and again before the first write |
| 7 | `docs/reverse-unlock.md` prescribed `edl wf <file>` | that command writes from **sector 0** — it overwrites MBR/GPT | partition-aware `edl w devinfo …` with an explicit warning |
| 8 | Sahara implementations reported success without a terminal ack | a stalled EDL session looked like a successful loader upload, and the next step (patching devinfo) would run on false information | success only on `DONE_RSP` status 0 or `RESET_RSP`, in both the Rust and Python uploaders; both state machines are unit-tested with wire transcripts |
| 9 | `sahara-rs` protocol IDs shifted from `0x0b`; `READ_DATA` fields read from the wrong offsets; the first packet was dropped | command mode unreachable, loader chunks never sent, timeouts instead of results | constants and offsets corrected against bkerler's implementation; first packet returned by the handshake; transcript tests |
| 10 | Tauri app invoked `oem device-info` unconditionally | wedges the whyred ABL until a physical reboot (measured, EXP-002) | verb removed; the app also gained a partition allowlist and serial confirmation |
| 11 | Tauri UI used `window.__TAURI__` with `withGlobalTauri` unset | the app's buttons did nothing at all | flag enabled, CSP restored, backend writes require `unlocked=yes` and a matching serial |
| 12 | `download` phase OKAY was not consumed before `flash:` | the stale OKAY could be reported as flash success | terminal response read before issuing `flash:<part>` |
| 13 | Rootfs image shipped with the password `root:whyred` | a public default credential on a device that will host containers | root ships locked; the password is set on first console login |
| 14 | Proxmox release key trusted blindly via `trusted.gpg.d` | a swapped key file would silently control the package sources | fingerprint must be supplied (`PROXMOX_KEY_FPR`), verified with `gpg --show-keys`, key isolated with `signed-by` |

## Correctness of the build pipeline — fixed

- `scripts/build-edk2.sh` copied *any* `*.img`/`*.fd` the VM happened to leave
  in `edk2-out` and never verified the result → output is normalized to
  `uefi_<device>.img` and its absence is a hard error.
- The lavender EDK2 port script existed but was never invoked → the wrapper
  now applies it (`PORT_ONLY=1`) before building.
- `scripts/build-rootfs.sh` was hard-wired to whyred → `DEVICE` is threaded
  through and the matching kernel is required instead of silently packing the
  wrong one.
- `make-dist.sh` silently skipped missing artifacts and rewrote the manifest
  in place → the flashable set is mandatory and the manifest is written
  atomically.
- The guest rootfs script suppressed failures of the self-bind mounts,
  `dpkg --configure -a` and `e2fsck` → all are fatal now.
- `scripts/build-rootfs.sh` passed `--cmdline_extra` while clap expects
  `--cmdline-extra`: the Plan B step would have aborted **after** a 40-minute
  kernel build. Found by running the wrapper, not by reading it.
- Unpinned kernel fragment URL → the repo copy is preferred over raw GitHub.
- Kernel and edk2-msm commits are now printed into the build log so artifacts
  are traceable.

## EDL tooling — restructured

- `tools/edl-devinfo.py` was deleted: it duplicated firehose/GPT handling
  that bkerler/edl already does correctly, mixed XML with payload bytes, and
  wrote the `configure` response to `lavender-devinfo-full.bin` while claiming
  it was a devinfo dump. Reads now go through the maintained client.
- `tools/edl-recon.py` keeps the pyusb Sahara upload (the only transport that
  works on this macOS host) with a pure, tested state machine.
- `tools/analyze-devinfo.py` no longer advertises a magic scanner it does not
  have, and reports longest-match keywords explicitly labelled as
  observations, never as patch offsets.

## Documentation — reconciled with reality

- `community port / Debian 12 / Svelte` → official Proxmox arm64 on trixie and
  a static HTML UI.
- Non-existent `scripts/build-all.sh` and `pve/mkrootfs.sh` → the real entry
  points, now also documented in `README.md` and `ARCHITECTURE.md`.
- Test counts 7/7 → 19 (6+6+2+4 in `tools/`, 1 in `mibox-core`), then 27 with
  the property and Python tests added afterwards.
- `userdata 54.94 GiB` → 51.37 GiB (55,155,064,320 B) matching the raw dump.
- DRAM base `0x80000000` → `0x40000000` (matches Vivanta hardware notes).
- Plan B is the default everywhere (ADR-001 said so; the guide and script did
  the opposite).
- Backups of `boot` + `userdata` are now a stated prerequisite, and the guide
  no longer promises EDL recovery "always works".
- `dist/SHA256SUMS` described 10 artifacts while 8 were absent → regenerated
  from what actually exists; `shasum -c` passes.

## Follow-ups added during the night mission

- `bootimg-rs validate --profile kernel|uefi` — pre-flash header validation,
  wired into `flash_all.sh` so a wrong or truncated boot image is refused
  before any write.
- Property tests for boot images (deterministic generator, 4 page sizes ×
  v0–v2, stable re-pack, truncation boundaries).
- `tools/test_tools.py` — unit tests for both EDL state machines and the
  devinfo analyser.
- `docs/exp003-lavender-edl.md` — the measured lavender EDL session, including
  the firehose NAK that explains where the session stopped.
- `scripts/check.sh` and a GitHub Actions workflow (Linux + macOS) as the
  single validation entry point.
- `pve/proxmox-release-key.fpr` — the observed release-key fingerprint, stored
  with an explicit "verify before trusting" note; the build still requires the
  operator to export it.
- Streaming `sparse-rs` encoder — removes the ~17 GiB peak that made the
  conversion unrunnable on a 12 GiB build VM.
- `scripts/build-rootfs.sh` flag fix (`--cmdline-extra`) and the rootfs rebuild
  guards found by actually running the pipeline, not by reading it:
  - `--cmdline_extra` → `--cmdline-extra` (clap kebab-case): the Plan B step
    would have aborted after a 40-minute kernel build;
  - a chroot from an older build (with `proxmox-ve` and its kernel stack) was
    silently reused — now a `.pve-build` marker forces a clean tree;
  - **ADR-003 was not implementable as written**: apt installs Recommends, and
    `pve-yew-mobile-gui` Recommends `proxmox-ve`, which Depends on
    `proxmox-default-kernel`; the kernel stack then fails to configure inside
    a chroot. Fixed with `--no-install-recommends` plus an explicit
    `proxmox-firewall`;
  - an aborted run left `/proc` and `/sys` bind-mounted inside the chroot, so
    the next `rm -rf` could not delete it and the build wedged forever: binds
    are now cleared individually before the wipe and on exit;
  - `hostname` inside a chroot changed the **build VM's** hostname (no UTS
    isolation), which broke `sudo` there — removed;
  - `/dev/pts` is now mounted inside the chroot (apt complained).
